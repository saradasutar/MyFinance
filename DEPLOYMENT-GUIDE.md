# Private Investment Dashboard

A lightweight portfolio dashboard with:

- **Frontend:** GitHub Pages (HTML, CSS and vanilla JavaScript)
- **Backend:** Google Apps Script Web App
- **Storage:** Private Google Sheet in Google Drive
- **Backups:** Daily JSON backup files in a private Drive folder
- **Prices:** Google Finance for supported stocks/ETFs and AMFI daily NAV for Indian mutual funds
- **Access:** Username/password, expiring sessions and separate data for each user

## Part A — Set up the Google backend

### 1. Create an Apps Script project

1. Open **script.google.com** while signed in to the Google account that will own the data.
2. Click **New project**.
3. Rename it to **Investment Dashboard Backend**.
4. Open the supplied `google-apps-script/Code.gs` file, copy all its contents, and replace the default Apps Script code.

### 2. Add the manifest

1. In Apps Script, open **Project Settings**.
2. Enable **Show “appsscript.json” manifest file in editor**.
3. Open `appsscript.json` in the editor.
4. Replace its contents with the supplied `google-apps-script/appsscript.json`.

### 3. Run the one-time setup

1. At the top of the editor, select the function **setupSystem**.
2. Click **Run**.
3. Approve the requested Google permissions.
4. Open **Executions**, select the completed setup execution, and read its logs.
5. Copy the temporary credentials shown there:
   - Username: `admin`
   - Temporary password: generated by the script

The setup function automatically creates:

- a private Drive folder named **Investment Dashboard Data**;
- a Google Sheet named **Investment Dashboard Database**;
- a **Backups** folder;
- Users, Sessions, Holdings, Watchlist, Quotes, Settings and AuditLog sheets;
- a six-hour mutual-fund NAV refresh trigger;
- a daily Drive-backup trigger.

### 4. Deploy the Apps Script Web App

1. Click **Deploy → New deployment**.
2. Select **Web app**.
3. Description: `Investment Dashboard API`.
4. **Execute as:** Me.
5. **Who has access:** Anyone.
6. Click **Deploy** and approve permissions if prompted.
7. Copy the Web App URL ending in `/exec`.

Do not use the `/dev` testing URL.

### 5. Configure the frontend

Open `github-frontend/config.js` and replace:

```javascript
API_URL: 'PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE'
```

with the copied `/exec` URL, for example:

```javascript
API_URL: 'https://script.google.com/macros/s/AKfy.../exec'
```

No password, Sheet ID, Drive ID or private key should be placed in the GitHub files.

## Part B — Publish the GitHub frontend

### 1. Create a repository

1. Sign in to GitHub.
2. Create a new repository, for example **investment-dashboard**.
3. It may be public because it contains only frontend code. Your portfolio data remains in the private Google Sheet.

### 2. Upload the frontend files

Upload only the contents of the `github-frontend` folder to the repository root:

- `index.html`
- `styles.css`
- `app.js`
- `config.js`
- `.nojekyll`

Commit the files to the `main` branch.

### 3. Enable GitHub Pages

1. Open the repository **Settings**.
2. Open **Pages**.
3. Under **Build and deployment**, choose **Deploy from a branch**.
4. Select branch `main` and folder `/ (root)`.
5. Save.
6. Open the Pages URL after GitHub publishes it.

### 4. First login

1. Sign in with `admin` and the generated temporary password.
2. Click the profile circle or **Change password**.
3. Set a strong permanent password.

## Adding investments

### Indian stock or ETF

Example:

- Type: `STOCK`
- Name: `Reliance Industries`
- Ticker: `RELIANCE`
- Exchange: `NSE`
- Units: your total units
- Total invested amount: total acquisition cost

The backend creates a Google Finance formula in the Quotes sheet. Newly added symbols may take a little time to populate. Use the refresh button afterward.

### Indian mutual fund

Use the fund's numeric **AMFI scheme code**, not an ISIN and not only the scheme name.

Example fields:

- Type: `MF`
- Name: the complete scheme name
- AMFI scheme code: numeric code from AMFI
- Units: units held
- Total invested amount: total acquisition cost

Mutual-fund NAVs are end-of-day values. The script refreshes tracked AMFI codes every six hours and when the dashboard refresh button is used.

### Manual price

Use **Manual current price** when:

- Google Finance does not support a security;
- a mutual-fund code is temporarily unavailable;
- the investment is an FD, bond, gold item or other asset;
- you want to override an automatic quote.

Remove the manual price later to resume automatic pricing.

## Watchlist

The watchlist tracks possible future investments separately from holdings. Add:

- asset name and code;
- target buy price;
- priority;
- reason or valuation notes.

The overview shows items closest to the target price.

---

## User administration

An administrator can:

- create additional usernames;
- assign User or Admin role;
- reset passwords;
- disable or re-enable accounts.

Each account sees only its own holdings and watchlist. Administrators manage accounts but do not automatically see another user's portfolio through the dashboard.

## Performance design

The project is optimized for a small personal/family portfolio:

- no framework or chart library;
- one consolidated bootstrap request;
- instant rendering of the last successful browser cache;
- automatic quote rows stored in one Sheet;
- mutual-fund downloads handled by Apps Script, not the browser;
- LockService protects concurrent writes;
- sessions are temporarily cached to reduce Sheet reads.

Keep historical transactions in a separate archive if you expect tens of thousands of rows. This version is designed for consolidated current holdings rather than full tax-lot accounting.

---

## Security notes

- GitHub Pages is public static hosting, so it cannot safely hold passwords or secret keys.
- Password checking happens only in Apps Script.
- Passwords are stored as salted, iterated hashes, not plain text.
- Session tokens expire after 12 hours and only token hashes are stored in the Sheet.
- The Google Sheet and Drive folders must remain private.
- Deploy the web app as the owner and select **Anyone** only because the application performs its own login check.
- Change the temporary administrator password immediately.
- Do not publish `Code.gs` in the public frontend repository unless you are comfortable sharing the server source. It contains no passwords, but keeping backend code separate is simpler.

This is suitable for personal tracking, not for regulated brokerage, payment or institutional custody systems.

## Updating the project

### Frontend update

Edit a GitHub file and commit it. GitHub Pages republishes automatically.

### Backend update

1. Replace or edit `Code.gs` in Apps Script.
2. Click **Deploy → Manage deployments**.
3. Edit the web-app deployment.
4. Select **New version** and deploy.

The `/exec` URL normally remains the same.

## Troubleshooting

### “Backend is not configured”

The URL in `config.js` was not replaced, is not an Apps Script URL, or does not end in `/exec`.

### Login page says the backend response is unreadable

Check the deployment:

- deployment type is **Web app**;
- execute as **Me**;
- access is **Anyone**;
- the URL ends in `/exec`;
- `setupSystem()` was run successfully.

### Stock price remains pending

- confirm the exact exchange ticker;
- inspect the Quotes sheet for the `GOOGLEFINANCE` result;
- try `BOM` for BSE securities;
- wait briefly and refresh;
- use a manual price if unsupported.

### Mutual-fund NAV remains pending

- confirm that the value entered is the numeric AMFI scheme code;
- run `refreshMutualFundNav()` once from Apps Script;
- inspect Apps Script **Executions** for an AMFI fetch error;
- temporarily use a manual NAV.

### Forgot the admin password

Run `resetAdminPassword()` in Apps Script and read the newly generated temporary password from the execution log.

### Changed backend code but nothing changed

Create a **new deployment version** from **Deploy → Manage deployments**. Saving code alone does not update an existing `/exec` deployment.
